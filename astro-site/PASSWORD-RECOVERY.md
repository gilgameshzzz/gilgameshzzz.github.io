# 加密文章的密码怎么办

这个博客里有几篇标着 🔒 的文章，正文在页面里是密文，要输密码才能读。
这份文件说明**密码在哪里**——它本身不包含密码，也不包含任何关于密码内容的线索。

---

## 如果你是读者

这些文章大多是写给我自己的复习材料或还没想好要不要公开的草稿，所以默认不对外。
想读的话直接找我要就行：GitHub 上开个 issue，或者用我主页上的联系方式。
说一下你是谁、想看哪篇，我一般会给。

不必去暴力破解。密文和 KDF 参数确实是公开的，但密码是 24 位随机串，
PBKDF2-SHA256 跑 31 万轮——你跑不出来的，问我快得多。

---

## 如果你是我

### 密码在哪

1. **密码管理器**，条目名 `blog-encrypted-posts`。这是权威来源。
2. 本机 `astro-site/secrets/post-passwords.json`，`{ "<slug>": "<密码>" }`。
   这个文件被 gitignore，永远不进仓库，所以它只存在于你当前这台机器上。

### 明文正文在哪

`astro-site/private/drafts/<slug>.md`。整个 `private/` 被 gitignore。
**这是工作区里唯一的明文副本**，仓库里没有，GitHub 上也没有。

### 改了文章之后怎么重新封装

```bash
cd astro-site
pnpm seal       # 同步存根 → 构建加密 → 检查产物里没有明文
```

`seal` 只在内容或密码变了的时候才重新加密（靠 `private/.seal-state.json` 里的指纹判断），
所以反复构建不会刷出一堆噪音 diff。

换了密码、或者怀疑指纹缓存不对，用强制版：

```bash
pnpm reseal     # 忽略指纹缓存，全部重新加密
```

提交前可以单独跑一次状态检查（CI 里也会跑同一个脚本）：

```bash
pnpm check:sealed
```

### 丢了会怎样

这是整件事里最该记住的部分。

| 丢了什么 | 后果 |
|---|---|
| 只丢密码 | 还能救。草稿还在，设个新密码 `pnpm reseal` 重新封装就行 |
| 只丢草稿 | 还能救，但很难受。得在浏览器里用密码解锁，把正文手抄回来，格式会丢 |
| **两个都丢** | **永久丢失。** 没有任何办法恢复 |

所以**别把它们放在同一个篮子里**：密码在密码管理器（有云端同步），
草稿在本地 + 一份独立的离线备份。这两者不要只存在于同一台机器上。

## 这个加密能挡住什么，挡不住什么

**能挡住的**：随手点进来的人、搜索引擎、爬虫。密文是 AES-256-GCM，
密钥由 PBKDF2-SHA256 跑 31 万轮导出，GCM 自带完整性校验——密码错了是解密失败，
不会产出看起来像那么回事的乱码。

**挡不住的**：密文和 KDF 参数全都是公开发布的，任何人都可以下载回去离线爆破。
**唯一的防线是密码强度**。所以这里用的是 24 位随机串，不是什么好记的词。

**所以这适合什么**：不想随便公开、但万一泄漏了也不致命的内容。
公司资料、凭据、真正敏感的东西**不要**往这儿放——那些东西根本就不该进公开仓库。

另外说清楚一点：早期版本的加密是「构建期加密」，正文明文是提交进公开仓库的，
只有构建产物才是密文。那段时间发布过的内容应当按**已经公开过**来对待。
现在的机制（只提交密文）是在那之后才改的。
